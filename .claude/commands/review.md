現在のブランチの実装が、要件定義・詳細設計・フェーズの完了条件に沿っているかをレビューしてください。

## 手順

1. `要件定義書.md` を読み、プロジェクト概要・機能要件・非機能要件を把握する
2. `docs/01_機能要件.md` および該当する `docs/features/F0X_*_機能定義書.md` を読み、対象機能の完了条件・API設計・DB設計を把握する
3. `git diff main` で現在の変更差分を確認する
4. 以下のチェック項目を順番に確認し、結果を報告する

## チェック項目

### 要件との整合性
- [ ] 実装した機能が要件定義の機能要件を満たしているか
- [ ] 要件にない機能が勝手に追加されていないか
- [ ] フィールド名・型・制約が `docs/06_データ設計.md` の DB 設計と一致しているか

### 設計との整合性
- [ ] ファイルパスとコンポーネント名が `docs/07_技術仕様.md` のディレクトリ構成と一致しているか
- [ ] API のエンドポイント・メソッド・レスポンス形式が機能定義書の API 設計と一致しているか
- [ ] 使用している技術・ライブラリが技術スタックに沿っているか（React + TypeScript / Spring Boot 3.5.x / PostgreSQL 17）

### フェーズ完了条件
- [ ] 機能定義書に記載された当該機能の完了条件をすべて満たしているか
- [ ] 次フェーズの作業が混入していないか（スコープ超過がないか）

## 報告フォーマット

問題がない場合:
「要件定義・設計との整合性に問題はありません。対象機能の完了条件をすべて満たしています。」

問題がある場合:
| 種別 | 箇所 | 内容 | 対応 |
|------|------|------|------|
| 不一致 | ファイル名:行番号 | 設計では X だが Y になっている | Z に修正する |
| 不足 | - | 完了条件「〇〇」が未実装 | 実装を追加する |
| 超過 | ファイル名 | 今回スコープ外の作業が含まれている | 別ブランチに分離する |
